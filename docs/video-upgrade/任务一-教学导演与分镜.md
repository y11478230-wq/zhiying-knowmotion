# 任务一：通用教学导演与内容规划

## 目标

设计一条能适用于用户任意知识主题的生成规划链路。系统收到主题后，自动判断学习目标、内容类型、讲解逻辑和合适的视觉表达，再生成结构化脚本与分镜。交付重点是通用规则与跨主题效果，不是只打磨一条样片。

## 负责人

教学导演 / 内容规划负责人（成员 A）

## 工作范围

1. 定义从主题到视频脚本的统一流程：识别主题、受众和难度；明确学习目标；选择解释方法；组织讲解节奏；生成镜头计划。
2. 设计主题分类与表达策略映射。至少覆盖数学推导、科学过程、编程操作、历史地理叙事、概念辨析等常见类型；遇到混合主题时允许组合多种方法。
3. 建立通用教学结构：提出问题、建立直觉、演示或论证、解释关键条件、应用检验、回扣问题。结构可依主题调整，不强制每条视频使用相同模板。
4. 设计生成提示与输出 Schema。每个镜头需说明学习目的、旁白、画面主体、初始状态、动作、动作触发语句、字幕、时长、前后镜头关系和所需素材。
5. 定义事实与能力边界：不确定的知识需保守表达；不编造实验数据、代码运行结果、教材页码或引用；无法生成可信演示时提供明确的替代表达或提示补充资料，不能用纯文字卡片伪装成完成的讲解。
6. 准备跨主题验证集并维护参考结果。首批至少 8 个主题，覆盖上述 5 类内容，每类至少 1 个常见主题与 1 个边界或混合主题。
7. 与成员 B 对齐可用视觉能力，与成员 C 对齐配音和时长约束；根据实际渲染回看片段，迭代规划规则。
8. 参考 `参考视频-生成Agent规范.md`，给每个需要说明的概念设计具体例子。分镜写明图片的教学作用、素材类型与所需动作；优先让照片或插画建立直觉，再用矢量标注、箭头和图解解释关系。

## 交付物

- `director-spec.md`：通用导演流程、主题分类规则、解释方法选择规则和失败处理方式。
- `scene-schema.json`：全主题统一的脚本与分镜结构定义，含必填项、可选项和字段校验规则。
- `prompt-templates/`：规划、脚本、分镜及自检提示模板；以可组合模块组织，不为每个单一主题复制一套提示词。
- `benchmark-topics.json`：至少 8 个跨主题输入及预期学习目标、表达方式和主要检查点。
- `sample-outputs/`：验证集的结构化生成结果，标出人工审核记录。
- `asset-plan.json`：逐镜素材需求、对应旁白、来源类型、复用对象 ID 和需要人工核查的图片内容。

分镜共用字段建议：`topicType`、`learningGoal`、`explanationMethod`、`scene.id`、`scene.purpose`、`scene.narration`、`scene.duration`、`scene.visual.type`、`scene.visual.objects`、`scene.visual.actions`、`scene.caption`、`scene.transition`、`scene.assets`。

## 验收标准

- 8 个以上验证主题都生成结构完整的脚本和分镜；不能只对样片主题有效。
- 不同类型会选择有区别的讲解逻辑和视觉方法，不是统一套用“标题＋卡片＋要点”。
- 每个关键知识步骤都有相应的演示、比较、叙事或图解计划，并说明画面为何有助于理解。
- 每个动作绑定到旁白语义或明确的时间点；分镜包含停留观察和镜头衔接安排。
- Schema 可以自动校验；缺字段、未支持能力或不确定事实能被识别并清楚反馈。
- 关键知识与例题经人工抽查，事实错误、虚构结果和无依据结论有记录并持续修正。
- 具体例子包含对象、条件、变化和结果；所选图片能够帮助理解对应旁白，而非仅作装饰。

## 协作边界

成员 A 对通用教学逻辑、主题分类、提示模板、结构化分镜和知识表达负责。成员 B 维护可用画面能力目录；成员 C 提供真实时长、合成和回看反馈。新主题的视觉能力若不存在，A 标记能力需求并与 B 共同定义，不擅自假设已经实现。
