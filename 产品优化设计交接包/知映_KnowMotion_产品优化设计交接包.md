版本：V1.0  
用途：供接手设计与开发的队友在原有源码和功能基础上渐进优化  
基线日期：2026 年 11 月 14 日

## 0. 交接结论与阅读约定

本项目不是重写项目。接手者必须以第二阶段可靠性修复版本为功能基线，以本文件为产品与视觉基线，在取得原始源码后逐页替换界面、逐项接通既有能力，再建设新增能力。任何 UI 改造都不得以删除真实功能、改写既有数据含义或用假进度、假数据、假导出代替真实链路为代价。

本文使用三类状态标记，开发、排期和验收时不得混用：

| 标记 | 含义 | 处理方式 |
|---|---|---|
| **A 已有且实测可用** | 第二阶段已验证可运行的本地能力或已修复行为 | 改版前建立回归用例；改版后必须保持 |
| **B 已修复但依赖环境** | 代码路径或修复已存在，但运行依赖 API、TTS、FFmpeg、操作系统或配置 | 保留准确状态反馈；环境缺失时明确降级，不伪装成功 |
| **C 规划新增尚未实现** | 产品目标中的新页面、账号、社区或云端能力 | 先设计数据契约和后端方案，再实现真实闭环 |

> 关键事实：当前工作区未包含第二阶段原始 ZIP 或可核验源码。本交接包不假设任何旧本地路径有效。队友应先提供第二阶段可靠性修复版源码，并在该原项目上实施；收到源码后，第一项工作是重新盘点并用证据校准 A/B/C 状态。

## 1. 项目定位与目标

知映 KnowMotion 是“AI 知识视频创作平台 + 创作者社区 + 个人作品管理”。它不是单一的一键视频生成器，也不是无主题的短视频平台。

核心主线为：提出知识主题或添加参考资料 → AI 理解与规划 → 脚本与智能分镜 → 视频工坊编辑 → 预览与导出 → 保存到作品库 → 经用户主动选择后发布到灵感社区。

产品目标：

1. 用接近 GPT 的低门槛对话入口启动创作，让用户先表达知识主题，再逐步补充设置。
2. 保留从知识理解、文案、分镜、画面、配音、字幕、音乐、动画到导出的完整可编辑链路。
3. 以作品库沉淀项目、草稿、生成任务和导出结果，保证对话、项目和成品之间可追溯。
4. 建设以知识视频为中心的完整创作者社区，但社区的账号、互动、审核和文件服务必须按真实后端能力建设。
5. 手机端优先，兼容桌面浏览器；视觉统一为白色与浅薄荷绿，轻量、清晰、可信。

产品边界：创作是产品主线，社区是内容生态。两者通过“从已完成作品发布”和“从社区作品获得灵感”连接，但社区不可阻塞本地创作与导出。

## 2. 原项目保护原则

### 2.1 必须保留

- 原项目目录与可运行入口，不另起一套替代工程。
- 原生 HTML/CSS/JavaScript + Node HTTP 的技术栈，除非源码复查证明某项变更必要并经确认。
- 现有数据结构、字段语义、文件命名、接口行为和业务能力；新增字段采用向后兼容迁移。
- Python TTS、Canvas 渲染、预览与导出链路中的既有实现和回退逻辑。
- `/api/status` 的准确状态：只报告真实可用的服务与依赖，不能把“代码存在”报告成“已可用”。
- 已修复的安全监听配置。默认保持安全的本机监听；若需局域网或公网访问，必须显式配置并说明风险。

### 2.2 渐进优化方法

1. 收到源码后先运行、记录基线，再修改。
2. 先抽取设计令牌和公共组件，不先改业务函数。
3. 按页面或流程小步替换 DOM 与样式，使用适配层连接旧数据和旧事件。
4. 每完成一页即做原功能回归；不要等全部改完再测试。
5. 数据结构只能增量扩展。需要迁移时，先备份、提供迁移脚本与回滚说明。
6. 新社区能力与原创作链路隔离部署或模块化接入，失败时不影响本地创作。

### 2.3 禁止事项

- 禁止推倒重写、换框架或复制出“新版项目”后遗弃原项目。
- 禁止删除看似旧但仍承载业务的函数、接口、数据字段和导出步骤。
- 禁止用静态卡片、固定百分比、延时动画或样例 MP4 冒充真实生成、预览和导出。
- 禁止把浏览器本地数据直接宣称为账号云数据。
- 禁止把社区点赞、评论、关注、消息、审核做成只改前端数字的按钮。
- 禁止在依赖缺失时返回成功；必须显示可操作的错误与配置建议。
- 禁止未经用户确认上传参考资料、项目、音频或视频到第三方服务。

第二阶段检查所见技术构成为：原生 HTML/CSS/JavaScript、Node HTTP 服务、Python TTS、Canvas。未见可确认的数据库、账号系统、云端项目管理、真正的图片生成模型或视频生成模型。

| 能力或事实 | 状态 | 交接要求 |

| Canvas 画面或预览相关链路 | **A 已有且实测可用** | 先建立视觉与导出回归样例，再改 UI |
| 第二阶段可靠性修复成果 | **A 已有且实测可用** | 以修复版本为唯一功能基线，不从更早版本开始 |
| `/api/status` 准确反映依赖状态 | **A 已有且实测可用** | 保留状态语义与前端提示，新增依赖也纳入该状态模型 |
| 安全监听配置 | **A 已有且实测可用** | 保留默认安全边界，不为手机联调直接开放所有网卡 |

| 真正图片或视频生成模型 | **C 规划新增尚未实现** | 需独立选型、成本、授权、异步任务和内容安全方案 |

| 完整社区后端 | **C 规划新增尚未实现** | 不得把规划页面描述成已有服务 |

### 3.2 收到源码后的首轮核验

- 记录操作系统、Node、Python、FFmpeg、环境变量和启动命令，不记录密钥值。
- 调用 `/api/status`，对照真实进程、二进制和配置，检查无误报。
- 建立最小回归样例：打开首页、发起创作、编辑文案和分镜、TTS、Canvas 预览、保存、导出。
- 盘点数据存储位置、项目 ID、对话 ID、任务 ID、资源路径和错误码。
- 输出“能力证据表”：入口、输入、成功输出、失败表现、依赖、复测结果。
- 若实测与本交接包状态不同，以证据更新状态并通知产品负责人，不自行扩大范围。

## 4. 视觉设计规范

### 4.1 设计语言与色板

设计关键词：极简、干净、柔和、AI 原生、一致。禁止深色科技风、紫色渐变、大面积高饱和色、大型 3D 图标和不同页面随意换绿。

| 令牌 | 建议值 | 用途 |
|---|---:|---|
| `--color-bg` | `#FFFFFF` | 主背景 |
| `--color-surface` | `#F4F9F7` | 雾白绿卡片、分区背景 |
| `--color-brand` | `#078D70` | 主按钮、选中、关键进度 |
| `--color-brand-soft` | `#E7F6F1` | 次按钮、标签、悬停 |
| `--color-text` | `#153D43` | 主文字 |
| `--color-text-2` | `#56706F` | 辅助文字 |
| `--color-border` | `#DCEBE6` | 边框与分隔 |
| `--color-danger` | `#C64242` | 删除、失败、举报 |
| `--color-warning` | `#B66A13` | 依赖缺失、待确认 |
| `--color-success` | `#078D70` | 成功状态 |

颜色对比度须满足 WCAG AA：正文至少 4.5:1，大字至少 3:1。状态不能仅靠颜色表达，必须同时有图标或文字。

### 4.2 字体、间距、圆角与阴影

- 字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 标题 28/34、页面标题 22/30、区块标题 18/26、正文 16/24、辅助 14/20、说明 12/18；正文不小于 14 px。
- 字重以 400、500、600 为主，不用大段粗体。
- 4 px 网格；常用间距 4、8、12、16、20、24、32、40。
- 页面左右安全内边距 16 px；主要内容最大宽度在宽屏上受控。
- 卡片圆角 18–24 px；输入框 16–20 px；主按钮胶囊或 16–24 px；小标签 999 px。
- 阴影轻柔：`0 8px 30px rgba(21,61,67,.08)`；边界优先用浅灰绿边框，不叠加重阴影。
- 动效 160–240 ms，使用淡入、位移 8–16 px 或抽屉滑动；遵从 `prefers-reduced-motion`。

### 4.3 手机适配与安全区

- 基准画布 390 × 844 CSS px，重点覆盖 360–430 px；同时检查平板和桌面窄窗。
- 使用 `env(safe-area-inset-top/right/bottom/left)`；底部导航和固定按钮不得遮住系统手势区。
- 可触控目标至少 44 × 44 px，相邻目标留足间距。
- 键盘出现时输入框和主要提交按钮可见；抽屉、弹窗和编辑面板可滚动。
- 不允许横向溢出、内容被固定栏遮挡、刘海遮住标题或长中文截断。
- 横竖屏切换不丢编辑内容；低网速与离线时显示状态并保留本地草稿。

## 5. 首页与历史记录抽屉

首页严格以用户最终确认的两张参考图为结构基准，不再重新发明布局。实现时应向产品负责人索取原图；若图片未随源码交付，以以下规范为准，禁止凭想象大改。

### 5.1 GPT 式首页默认状态

1. 顶部左侧：绿色“知”方块、知映文字、简约向下展开图标。顶部不展示历史摘要或“清空”快捷项。
2. 顶部右侧：消息铃铛与头像。未接账号系统前，头像仅表示本地个人入口并清楚标注。
3. 中部主标题：“让知识，动起来”。副标题：“用一句话，生成有趣的知识视频”。
4. 大型对话输入区：多行主题输入；添加参考资料；创作设置；发送按钮。发送前校验空内容和附件状态。
5. 推荐问题：三条左右，点击后填入输入框，允许继续编辑，不应直接无确认发起昂贵任务。
6. 底部固定四栏：首页、灵感、作品库、我的。AI 创作从首页输入框启动，不设置中间加号。

### 5.2 搜索与历史记录抽屉

- 点击顶部展开图标，左侧抽屉滑出并覆盖首页部分区域；焦点进入抽屉，背景加轻遮罩。
- 点击遮罩、再次点击图标或按 Esc 关闭；关闭后焦点返回触发按钮。
- 顶部为品牌名称和“新建对话”；下方是搜索框。搜索匹配标题、主题和可索引摘要，结果高亮并支持清除。
- 历史记录按“今天、昨天、7 天内、更早”分组；时间边界采用本地时区并处理跨日刷新。
- 单条显示标题、最近更新时间和状态；支持打开、重命名、删除。删除为可撤销或二次确认操作。
- 点击记录必须恢复对应对话、输入、附件引用、创作设置以及关联项目；缺失资源要说明，不静默新建。
- 新建对话不覆盖旧项目，先持久化当前未保存输入或询问用户。
- 底部提供清空历史记录与个人账号入口。清空前弹窗说明范围、不可恢复内容与关联项目是否受影响；默认只清对话索引，不级联删除作品和导出文件。输入确认后执行，并给出结果。
- 空状态、搜索无结果、数据损坏和读取失败分别呈现；本地模式不得暗示云同步。

## 6. 四个底部入口

| 入口 | 核心职责 | 不应承载 |
|---|---|---|
| 首页 | 对话式创作入口、历史、创建新项目 | 社区瀑布流、复杂项目管理 |
| 灵感 | 知识视频发现、搜索、互动、发布入口 | 未完成草稿编辑 |

## 7. AI 创作完整流程

下列页面首先是界面与交互目标。凡涉及真实 AI、TTS、视频模型或 FFmpeg 的功能，必须依据第二阶段实测标记为 A 或 B；新增模型能力仍为 C。

### 7.1 创作设置

- 自动带入首页主题与附件；支持文档、图片、链接时要显示格式、大小、上传/解析状态和删除。
- 设置项：目标受众；视频时长 30/60/90 秒或自定义；讲解方式；配音音色、语速与试听；画面风格；高级设置。
- 底部固定“生成视频方案”。提交前显示预计消耗仅限有真实计费数据时；设置保存到项目。
- 依赖未配置时，提交按钮不应无反馈；明确缺少何项、哪些步骤仍可使用。

### 7.2 生成中白底沉浸式页面

- 白色背景，中央显示当前阶段与真实任务状态：理解主题、整理知识、生成脚本、规划分镜、匹配画面、完成方案。
- 展示已完成、进行中、排队、失败和取消中；百分比只在后端有可信进度时出现。
- 提供取消、后台运行、失败重试。取消须说明已生成内容是否保留；重试从可恢复检查点继续。
- 刷新或离开后可通过任务 ID 恢复；长任务完成后进入消息中心。

### 7.3 智能分镜

- 顶部三栏：分镜、脚本、大纲。
- 每幕展示序号、标题、时长、缩略图、配音文案、画面描述和状态。
- 支持新增、删除、编辑、复制、拖拽排序、调整时长、单幕重新生成；删除和重生成前保护未保存修改。
- 总时长随分镜变化实时计算；错误幕可独立重试，不阻断其他幕编辑。

### 7.4 文案编辑

- 原始文案、AI 优化、对比查看；优化选项包括更简洁、更生动、适龄、口语化。
- “保持知识含义不变”默认开启。AI 结果作为候选版本，用户明确应用后覆盖当前稿。
- 支持保存、撤销、重做、版本对比和未保存离开提醒；不覆盖原始版本。

### 7.5 画面模板

- 分类：知识动画、信息图、场景演示、代码演示、数据图表、公式推导。
- 每项含缩略图、名称、适用场景、比例与预览；支持应用到当前镜头或全部镜头。
- 全部应用前显示影响范围并可撤销；缺失真实生成模型时使用 Canvas/既有模板能力，不声称生成了模型画面。

### 7.6 动画调整

- 动画时长、两点间距、速度、入场、出场、强调效果；实时预览。
- 重置只重置当前镜头或明确选择的范围；应用后写入分镜数据。
- 低性能设备降低预览质量而不改变导出参数，并提供减少动态效果选项。

### 7.7 视频工坊

布局：顶部返回、标题、保存；上部实时预览；中部横向分镜时间轴；底部编辑工具与属性面板。

| 工具 | 必备能力 |
|---|---|
| 文案 | 修改配音稿、保存版本、同步时长提示 |
| 画面 | 修改画面描述、选择素材或模板、替换与裁切 |
| 配音 | 音色、语速、试听、单幕生成、失败重试 |
| 字幕 | 内容、样式、位置、时间轴、开关与安全区预览 |
| 音乐 | 曲目、授权信息、音量、淡入淡出、与人声混音 |
| 动画 | 镜头效果、速度、入出场、实时预览 |

工坊不是播放器。编辑、保存、撤销、预览必须真实生效。自动保存要显示“保存中/已保存/保存失败”，并提供冲突处理。预览可降质，但内容、时间和音轨关系应与导出一致。

### 7.8 预览、导出与完成

- 比例 16:9、9:16、1:1；分辨率 720p、1080p；字幕和背景音乐开关。只有真实支持的组合可选。
- 导出前检查缺失资源、失败配音、超出安全区、授权受限音乐和磁盘空间。
- 导出任务显示真实阶段与日志摘要，允许后台运行、取消和重试；FFmpeg 缺失时明确标为 B 类依赖问题。
- 完成页支持播放、继续编辑、重新生成、下载、保存到作品库；分享或发布仅在成品文件校验成功后开放。
- 下载文件名可读、扩展名准确；失败任务不标为已完成。

## 8. 灵感社区完整页面与能力

**整体状态：C 规划新增尚未实现。** 除非收到源码后发现并验证真实后端，否则以下内容均不得标记为已有。社区需要数据库、身份认证、对象存储、内容审核、消息任务、权限与审计能力。

### 8.1 发现流与搜索

- 推荐、关注、热门、最新；分类包括科学探索、历史人文、数学物理、编程技术、生物医学、生活科普、人工智能。
- 卡片展示封面、标题、作者、时长、点赞/评论/收藏状态和授权标识。
- 搜索覆盖作品、主题、创作者和标签；提供最近搜索、筛选、排序、无结果和纠错建议。
- 推荐必须可解释并允许“不感兴趣”；第一期聚焦知识视频，不扩展为泛娱乐流。

### 8.2 视频详情与互动

- 播放器、标题、简介、标签、作者、发布时间、授权、相关作品。
- 点赞、取消点赞、收藏、取消收藏、分享均需幂等接口与登录状态处理。
- 评论支持发布、回复、评论点赞、删除自己的评论、分页与折叠；显示审核中、失败重试和已删除状态。
- 关注/取消关注在详情与作者页保持同步；计数以服务端为准，不以前端乐观值作为最终事实。

### 8.3 发布、创作者主页与消息

- 发布流程：从作品库选择已完成视频 → 设置封面 → 标题与简介 → 分类和标签 → 可见范围 → 下载授权 → 发布确认。
- 草稿、生成中或文件校验失败的作品不可冒充成品发布；上传显示进度、断点/重试和失败原因。
- 创作者主页含头像、昵称、简介、粉丝/关注数量、作品列表、收藏公开范围和关注按钮。
- 消息中心含生成完成、点赞、评论/回复、关注、系统和审核通知；未读数跨页面一致，支持逐条和全部已读。

### 8.4 下载授权、举报与审核

- 下载必须由作者授权；详情页显示“允许下载/仅站内观看/特定许可”。下载文件可附来源和授权元数据。
- 举报对象包括作品、评论和用户；原因、补充说明、证据、提交结果和处理进度可追踪。
- 审核需要机器/人工流程、状态、理由、申诉、审计日志和管理员权限；不得用“举报成功”代替实际处理系统。
- 发布前明确用户对素材、配音、音乐和生成内容的权利与责任；隐私内容不得默认公开。

## 9. 作品库与个人中心

### 9.1 作品库

- 分组：全部、草稿、生成中、已完成、失败；支持搜索、分类、排序和筛选。
- 卡片显示封面、标题、更新时间、状态、时长、比例、本地/云标识。
- 操作：继续编辑、重命名、复制、删除、下载、分享、发布。删除默认进入可恢复区或二次确认。
- 项目必须关联对话、创作设置、分镜、资源、任务与导出版本；缺失引用时显示修复入口。
- 账号/云端未实现前明确“本机作品”，不承诺跨设备同步。

### 9.2 我的

- 个人资料、账号与安全、创作统计、社区关系、收藏、下载、通知设置、隐私与授权、依赖状态、帮助反馈、关于。
- 在未实现账号系统时，以本地设置页呈现，并隐藏粉丝、跨设备同步等误导项。
- 提供数据导出与清理入口；清理前列出对话、草稿、成品和缓存的不同影响。

## 10. 组件、状态、无障碍与安全区

### 10.1 公共组件

统一实现：顶部栏、底部导航、主/次/文字/危险按钮、输入框、搜索框、选择卡、标签、项目卡、作品卡、抽屉、底部面板、对话框、Toast、进度、骨架屏、空状态、错误页、离线条、媒体播放器、时间轴、文件选择器。

每个交互组件至少覆盖：默认、悬停（桌面）、按下、聚焦、选中、禁用、加载、成功、错误。禁用按钮要说明原因；异步提交期间防重复触发。

### 10.2 全局异常状态

- 空：解释为何为空，并给出一个主要下一步。
- 加载：短加载用骨架屏，长任务用真实阶段；避免全页无限转圈。
- 错误：人类可读原因、保留用户输入、重试或返回；开发日志不得暴露密钥。
- 离线：顶部持续提示；允许本地编辑和排队，恢复网络后由用户确认重试上传。
- 权限：相机、麦克风、文件、通知在使用时再请求，拒绝后提供替代路径。
- 数据冲突：显示两个版本的来源与时间，允许选择、合并或另存。

### 10.3 无障碍

- 使用语义 HTML；标题层级、表单标签、错误关联和按钮名称完整。
- 键盘可操作抽屉、弹窗、菜单、时间轴核心功能；焦点可见且不被困住。
- 图片有替代文本；装饰图标隐藏于读屏；视频支持字幕，音频操作有文字状态。
- 不自动播放有声内容；支持减少动态效果；触控与文字缩放到 200% 后仍可完成任务。
- Toast 等动态状态使用合适的 `aria-live`，但不重复轰炸读屏。

## 11. 数据实体与页面关系建议

建议保持原有字段不变，在适配层中映射到以下概念模型；实际命名以源码为准。

| 实体 | 关键关系与用途 |
|---|---|
| User | 账号、资料、设置；C 类，未登录可用 LocalProfile |
| Conversation | 包含 Message，关联零或一个 Project；支持历史恢复 |
| Project | 创作主实体，关联设置、分镜、资源、任务和多个导出版本 |
| Asset | 原始附件、图片、音频、字幕、音乐；含来源、许可、校验和 |
| Storyboard / Scene | 项目的一对一/一对多分镜结构；顺序、时长、文案、画面、动画 |
| GenerationTask | AI、TTS、渲染、导出的异步状态、阶段、错误与重试信息 |
| Export | 成品文件、比例、分辨率、字幕、音乐、校验和与完成状态 |
| CommunityPost | 仅从有效 Export 发布；关联作者、许可、可见范围和审核状态 |
| Comment | 关联帖子与父评论；作者、状态、审核和删除信息 |
| Reaction / Bookmark / Follow | 用户与帖子或用户间的唯一关系；需幂等与计数一致性 |
| Notification | 事件接收者、类型、对象、已读时间；不存完整敏感正文副本 |
| Report / ModerationCase | 举报对象、理由、证据、处理、申诉与审计 |

页面关系：主页创建 Conversation，并可产生 Project；创作设置和所有编辑页读写同一 Project；生成中页面读取 GenerationTask；作品库以 Project 为中心；完成页基于 Export；灵感发布把有效 Export 转为 CommunityPost，不复制或破坏原项目；历史恢复通过 Conversation.projectId 回到关联项目。

所有实体应有稳定 ID、创建/更新时间和版本号。删除策略区分软删除与物理删除；资源引用计数归零后才清理文件。C 类云实体在后端方案确认前不可硬塞进现有本地 JSON 导致不可迁移。

## 12. P0 与 P1 分阶段优先级

### P0 先保证原链路不回退

1. 源码复查、依赖状态与回归基线，确认 A/B/C。
2. 设计令牌、基础组件、移动安全区和四栏导航。
3. 首页与历史抽屉：搜索、分组、恢复、单条操作、清空确认。
4. 创作设置、真实生成状态、智能分镜、文案、模板与动画页面重构。
5. 视频工坊真实编辑、保存、预览；TTS 与 FFmpeg 依赖错误可见。
6. 导出与作品库基本闭环；项目、对话和导出关联不丢失。
7. 全链路回归、无障碍基础、空错加载离线状态。

P0 的完成门槛是“原有能力全部保持且新 UI 可完成真实创作闭环”，不是“页面长得像设计稿”。

### P1 完整产品能力

1. 作品库高级管理、版本与恢复；我的和依赖设置完善。
2. 账号、数据库、对象存储、云项目与权限基础。
3. 灵感发现流、搜索、详情、点赞、收藏、关注、评论/回复。
4. 发布、创作者主页、消息、下载授权。
5. 举报、审核、申诉、审计、内容安全和运营工具。
6. 真正图片/视频模型的选型与接入（如确认需要），包括成本、排队、版权和降级。

完整社区是最终范围，但在后端基础建设前不可提前宣称完成。若需要更细排期，可在 P1 内拆为 P1.1 基础设施、P1.2 互动闭环、P1.3 治理与运营。

## 14. 给接手队友的实施说明

### 14.1 建议执行顺序

1. 请先提供原始第二阶段 ZIP 或可靠性修复版源码，不要依据旧路径寻找。
2. 解压或检出到受控工作副本，记录版本与校验信息，先不改代码。

### 14.2 开工前必须先确认的问题
